## How to Run

```bash
# 1. Create virtual environment (Python 3.12 required; 3.14 lacks binary wheels)
python3.12 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

# 2. Install dependencies
pip install -r requirements.txt

# 3. Execute notebooks in order (from submission/notebooks/)
cd submission/notebooks
jupyter nbconvert --to notebook --execute --inplace 00_setup_and_load.ipynb
jupyter nbconvert --to notebook --execute --inplace 01_preprocessing.ipynb
jupyter nbconvert --to notebook --execute --inplace 02_eda.ipynb
jupyter nbconvert --to notebook --execute --inplace 03_demand_prediction_agent.ipynb
jupyter nbconvert --to notebook --execute --inplace 04_tariff_pricing_agent.ipynb
jupyter nbconvert --to notebook --execute --inplace 05_monitoring_learning_agent.ipynb

# Or open interactively
jupyter lab
```

## Key Assumptions & Limitations

### Currency bridge
ACN-Data (Caltech/JPL, USA) has no price field. Revenue is **simulated** as
`tariff (₹/kWh) × kWhDelivered` against the **₹15/kWh fixed baseline** specified
in the problem statement. UrbanEV's real ¥/kWh prices are used **only to estimate
price elasticity of demand** (a log-log OLS proxy); they are not used as actual
tariffs. No causal claim is made about the INR elasticity.

### Elasticity
Price elasticity ε is estimated from UrbanEV via log-log OLS regression of volume
on price, controlling for hour-of-day and CBD status. This is an **associative proxy**,
not a causal estimate. A market-specific RCT or IV study would be needed for a true
INR elasticity.

### ACN demand model performance
The ACN station-hour dataset is relatively small (~15k sessions across ~74 stations
over 8 months) with sparse per-station observations. The HGB model achieves R² ≈ 0.06
on the test set, barely above the naïve seasonal baseline (R² ≈ 0.06). This is
**documented honestly** — the ACN model is used for tariff recommendation logic but
the ACN revenue gains should be interpreted cautiously.

### UrbanEV demand model performance
UrbanEV delivers strong results: R² = 0.993 (utilization) and R² = 0.996 (charging
load) on the held-out test set, far above the naïve baseline (R² ≈ 0.05). The large
scale (2.1M panel observations, 247 grids, 8,640 timesteps) provides ample signal
for the HGB models with lag and rolling features.

### RL feedback loop
The monitoring agent uses coordinate-ascent hill-climbing over two policy parameters
(surge_factor, discount_factor). This is a transparent, reproducible simulation —
it is not live deployment. Real-world deployment would require A/B testing and
customer behavioral data.

### Missing values
Lag features (1-slot, 12-slot, 288-slot) produce NaN at the start of each grid's
series. These are handled natively by HistGradientBoosting (no imputation needed).

## Model choices

| Component | Model | Rationale |
|---|---|---|
| Demand (utilization, load) | `HistGradientBoostingRegressor` | Pure Python, handles NaN natively, no native wheels on Python 3.12 |
| Congestion classification | `HistGradientBoostingClassifier` | Same |
| Pricing policy | Rule-based + scipy `minimize_scalar` | Transparent, interpretable, directly maps to PS thresholds |
| Feedback loop | Coordinate-ascent hill-climb | Simple, reproducible, shows clear convergence signal |
| Elasticity | Log-log OLS (`LinearRegression`) | Fast, interpretable, explicitly labelled as proxy |
